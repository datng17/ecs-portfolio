## 3. Triage history

The first scan was of the image built straight from the pinned base digest, with no package changes.
It found 52 vulnerabilities, all in Alpine packages that came with the base image, and every one had a fixed
version available:

  Severity  Package      CVE              Installed   Fixed
  HIGH      brotli-libs  CVE-2026-111497  1.2.0-r1    1.2.1-r0
  HIGH      curl         CVE-2026-92392   8.22.0-r0   8.23.0-r0
  HIGH      libcurl      CVE-2026-92392   8.22.0-r0   8.23.0-r0
  MEDIUM    zlib         CVE-2026-85091   1.3.2-r0    1.3.2-r1
  MEDIUM/LOW curl, libcurl  23 further CVEs each   8.22.0-r0   8.23.0-r0
  UNKNOWN   musl, musl-utils  CVE-2026-107891  1.2.6-r2  1.2.6-r3

  Totals: CRITICAL 0, HIGH 3, MEDIUM 3, LOW 44, UNKNOWN 2.

Bumping the base digest was not an option: the pinned digest was already the latest upstream build of the tag.

Fix (runtime stage of the Dockerfile, as USER 0 then back to USER 101):
  apk del --no-cache curl && apk upgrade --no-cache
- curl and libcurl are not used at runtime (the HEALTHCHECK uses busybox wget), so they were removed. That
  cleared 48 of the 52 findings and shrinks the attack surface.
- apk upgrade pulled the fixed brotli-libs, zlib and musl. brotli-libs stays installed because freetype
  (nginx image-filter module) depends on it.
- Trade-off: the image is less byte-for-byte reproducible than a pure digest pin, because the upgrade
  depends on the Alpine mirror at build time. Trivy in CI catches regressions. Drop the upgrade once upstream
  ships a rebuilt base.

Raw output (gitignored): evidence/raw/trivy-image.json, evidence/raw/trivy-vuln-table.txt,
evidence/raw/trivy-config.txt.
